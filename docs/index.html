Why this exists

The app that produces these numbers is a live service, and live services change, move and eventually stop. These files do not. Each snapshot records the scored universe and the exact model configuration behind it — weights, tier boundaries, adjustment caps — so the numbers stay interpretable long after anyone remembers how the scoring worked.

Each file also names the commit it was generated from. Check that commit out, run python scripts/publish_snapshot.py, and you get the same snapshot back. The archive is reproducible from the repository alone; it does not depend on the database or the deployed app.

Reading a score

A score is a position within the universe in that snapshot, not an absolute rating. Each signal is percentile-ranked across all accounts before it is weighted, so an account at 76 sits at roughly the 76th percentile of the accounts tracked at that time. It is not "76% ready", and it is not comparable to a score from a different snapshot with a different universe.

Tiers are quantiles of the live distribution — Tier 1 is the top 15% — so the shortlist stays a usable size as scores move. Every snapshot carries its own model.tier_quantiles and the resulting summary.tier_cutoffs.

The full derivation — correlation structure, PCA, the variance decomposition behind the weights, and what the rank transform does and does not fix — is in docs/scoring-model.md.
